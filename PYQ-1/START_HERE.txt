BEGINNER INSTRUCTIONS — FOLLOW IN ORDER

WHAT IS WHAT?
client.py = voter; server.py = Election Commission; crypto_helpers.py = small functions.
ballots.txt = input file (candidate number, constituency).

INSTALL ONCE: python -m pip install pycryptodome
TERMINAL 1: python server.py
TERMINAL 2: python client.py

CLIENT MENU:
1 = READ TXT (check input)
2 = GET PUBLIC KEYS AND TIMESTAMP FROM SERVER
4 = SUBMIT ALL 5 BALLOTS (automatically performs every client step)
5 = SEARCH BY CONSTITUENCY (try Udupi)
6 = TALLY VOTES (expected [2,2,1])
7 = AUDIT LOG
8 = TAMPERING TEST (expected rejection)

HOW TO CHANGE THE QUESTION:
- AES-128? Change get_random_bytes(32) to (16) in client.py.
- SHA-256? Change sha512() helper and all matching client/server uses.
- Hospital instead of votes? Change ballot fields and remove Paillier if not requested.
- Search by a different constituency? Change the text in ballots.txt, then menu 5.
- RSA-2048? Change RSA.generate(4096) to RSA.generate(2048) in crypto_helpers.py.

IMPORTANT LIMITATIONS:
This is a classroom demonstration, not a full secure e-voting protocol.
Server decrypts candidate; voter identity/public key not registered; timestamp is
server-issued HMAC rather than external TSA; Paillier ciphertext validity not proven;
threshold Paillier decryption is NOT implemented; SSE leaks IDs/access patterns;
no robust replay protection or secure network authentication.
